METHOD (g5/g63 — real bit-exact C-vs-hexa, no fabrication):
  Five deterministic instruction-byte sub-corpora, identical in C and hexa:
    A  every opcode byte 0..255 as a lone insn, 14-byte tail, buf_len=15  (256)
    B  MOV r,r/m (0x8B) over every ModR/M byte 0..255, fixed disp/sib tail (256)
    C  group-5 (0xFF) over every ModR/M byte 0..255 (INC/DEC/CALL/JMP/PUSH (256)

       short → `return 0` partial-state paths) + off>=buf_len edge

  has_imm has_disp disp modrm sib). 256*4 + 18 = 1042 rows.
  Gate = diff(C stdout, hexa stdout) == empty.

HONEST CAVEATS:
  - DIFFER-then-FIXED (real, not fabricated): first run differed on ONE row —
    the 0x8B-disp32 short-buffer case (sub-corpus E). C's decode_modrm_disp
    writes *modrm_out via the out-param BEFORE its own short-buffer `return 0`
    (the M2 write-before-fail contract), so the struct holds modrm=0x85 even
    though the composed call fails and i386_decode_one returns 0. The hexa port
    initially captured the leaf's modrm only AFTER the m_n==0 early-return guard.
    Fixed by capturing m_modrm/m_sib/m_disp/m_has BEFORE the guard in BOTH the
    /r and group-5 ModR/M branches — mirroring C's out-param semantics exactly.
    Re-run: byte-identical 1042/1042.
  - eip and bytes[] are not in the compared tuple. eip = eip_base+off is a
    trivial add (the harness always uses eip_base=0); bytes[] = code[off..off+len]
    is fully determined by the verified `len` field. Neither carries decode logic.
  - hexa `int` is 64-bit; C fields are int8/int16/int32. All corpus values stay
    within the C field ranges (imm sign-extended via the verified rd_s32/rd_s16/
    sx8 leaves; reg_a/reg_b in -1..7; prefixes <= 0x7FF), so the width difference
    never manifests — confirmed by the byte-identical diff.
  - i386_format_insn (C 305-...) is NOT ported here — it is a libc snprintf
    pretty-printer (string formatting, not decode logic) and is out of M4 scope;
